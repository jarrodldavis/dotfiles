# Global Coding Instructions

## Comments and Documentation

- Document the current implementation, not its development history.
- Never reference previous implementations, removed functionality,
  abandoned approaches, or earlier iterations in comments or documentation.
- Do not add comments explaining what code used to do.
- Only add comments when they clarify non-obvious logic, invariants,
  constraints, or design decisions relevant to the current implementation.
- Prefer self-documenting code over explanatory comments.
- Do not add documentation merely to summarize changes made during a task.
- Keep change summaries in the final response, not in source files.
- Remove obsolete comments and documentation when modifying code.
- Write code and documentation as though the reader has no knowledge
  of the conversation that produced them.
